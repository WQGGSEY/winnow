# 팩맨 연구 순환의 오프라인 사고실험

이번 작업은 유료 모델이나 새 실험을 실행하지 않았다. 실제 마지막 팩맨
관측을 새 입력 생성 코드에 통과시키고, 가정한 이후 계약에 대한 정상·오류
응답을 검증했다. 아래 Luna 행동은 예측이며 관찰 결과가 아니다. 연구 해법이나
학습 코드를 작성하거나 실행 상태에 주입하지 않았다.

## 구현에서 바뀐 연결

`ResearchWork 예측별 관측 의존성 → 실행 코드의 출력 위치·producer 선언 →
독립 검토자의 출력별 확인 → 실제 값·해시·경로 수집 → 예측별 해석 가능 범위 →
다음 해결책을 바꿀 작업 선택`

과거에는 요구한 count 이름과 코드의 출력이 구두 지침으로 연결됐다. 이제
실행 전에 모든 count의 파일·JSON pointer·producer를 지정해야 한다. 검토자는
각 출력의 생성 여부를 응답해야 하고, 실제 실행 후에는 해당 위치에서만 값을
읽는다. 다른 필드를 자동으로 같은 의미로 간주하거나 합산하지 않는다.

부분 결과는 일부 예측을 제한적으로 갱신할 수 있다. 필요한 관측이 없는
예측은 응답 스키마와 호스트 검증에서 모두 미결로 제한한다. 관측 수가 있다는
것과 과학적 해석이 타당하다는 것은 별도로 판단해야 한다.

## 실제 자료로 확인한 입력

마지막 실제 진단의 원본에는 다음 값이 있다.

| 구분 | game_count | record_count | eligible_group_count | alias_fraction |
| --- | ---: | ---: | ---: | ---: |
| feed-forward | 12 | 2,828 | 216 | 0 |
| recurrent | 12 | 2,838 | 0 | 0 |

각 값은 `/details/families/0/...` 또는 `/details/families/1/...` 경로와 원본
파일 해시를 함께 전달한다. recurrent의 마지막 0은 분모가 없으므로 효과
부재로 해석할 수 없다. feed-forward의 결과도 고정된 격자와 측정 정의를
넘어선 원인 부재나 해결책의 효능을 뜻하지 않는다.

캡처된 이전 planner packet을 재생했을 때 본문은 112,242에서 78,708바이트로
줄었다. 이는 instructions를 포함한 실제 모델 프롬프트나 과금 토큰 비교가
아니다. 과거 기록은 유지하고 관련 분석을 기본 입력에 집중한 결과다.

실제 과거 work에는 관측별 의존성 선언이 없고 요구된 최상위 count도 누락됐다.
그 work의 근거 불충분 판정을 소급 변경하지 않았다. 별도로 가정한 새 계약에서
두 family의 eligible count를 각각 연결했을 때, 첫 예측만 부분 갱신할 수 있었다.
recurrent 예측도 약화시키려는 잘못된 응답은 생성 스키마와 호스트가 모두
거절했다. 이는 의미적으로 좋은 설명을 자동 검증했다는 뜻은 아니다.

재생 코드와 결과는 다음에 있다.

- `runs/e2e/lab3-game-only/research-cycle-thought-experiment/replay.py`
- 같은 디렉터리의 `planner_input.json`, `result.json`

## Luna max가 같은 지점에 도달했을 때의 예상 행동

### 1. 관측은 있지만 출력 이름이 맞지 않는다

이전에는 실험이 끝났어도 모든 count가 missing으로 나타나 또 수리를 선택하기
쉬웠다. 이후에는 raw fact의 정확한 경로가 보인다. 현재 과거 work를 처리하는
합리적인 다음 선택은 기존 자료 분석이다. 어떤 기록이 어떤 수를 뜻하는지,
같은 게임을 양쪽 family에서 중복 집계하는지, 해석 범위가 어디까지인지를
확인한다. 새 실행이나 과거 계약 변경을 자동으로 요구하지 않는다.

예상 실패도 남는다. 모델이 소급 이름 변경으로 과거 작업을 성공 처리하려
할 수 있다. 호스트는 과거 support를 바꾸지 않으며, 해석은 새 분석 기록에
한계와 함께 남겨야 한다. 출력 schema 통과가 과학적 승인으로 바뀌지 않는다.

### 2. 한 family는 해석 가능하고 다른 family는 분모가 없다

이후 사전 선언된 계약에서는 첫 family의 제한된 관측을 설명 갱신에 사용할
수 있다. 다른 family는 미결로 남는다. 다음 질문은 전체 재실행이 아니라
분모 0이 관측량 부족인지, 그룹 정의가 현상을 포착하지 못하는지처럼 다음
측정 선택을 바꿀 구분이다. 기존 exclusion/strata 기록이 답할 수 있으면 먼저
그 기록을 사용한다. 추가 표본이 구분에 도움이 되지 않으면 측정법을 바꾼다.

모델이 분모 0을 효과 0으로 바꾸는 응답은 기계적으로 차단된다. 다만 어떤
새 측정법이 좋은지는 여전히 모델의 연구 판단이 필요하다.

### 3. 진단을 반복해도 개선 방법을 고르지 못한다

선택 지침은 완전한 원인 설명을 기다리지 않고 작은 직관적 개입을 시험할
수 있게 한다. 개입은 아직 가설이며, 원래 목표의 어떤 값을 개선할지와
동일 조건의 대조군을 함께 지정해야 한다. 이번 변경은 특정 RL 알고리즘이나
개입을 미리 공급하지 않는다. Luna가 자신의 메커니즘 가설과 프로그램을
작성해야 한다.

진단을 계속 선택한다면 그 결과가 다음 개입 선택을 어떻게 바꿀지 설명해야
한다. 실패한 측정법을 교체하는 데 과학적 가설의 반증까지 요구하지 않는다.
이 유도는 지침이므로 반복 진단을 반드시 막아 준다고 보장할 수는 없다.

### 4. 개입이 실패하거나 개선을 보인다

실패하면 실행 오류, 표본 부족, 유효한 무개선 관측을 구분한다. 유효한 부분은
해당 예측과 연결하고 다음 가정이나 개입을 바꾸는 데 사용한다. 단순한 부정
결론으로 원래 해결 목표가 완료되지는 않는다.

개선하면 고정된 목표에 대한 공정한 비교, 강한 comparator, 반복 실행,
일반화와 독립 confirmation으로 넘어갈 근거가 생긴다. 진단 지표 개선이나
일부 조건의 좋은 결과만으로 논문을 완성 처리하지 않는다. 이 단계까지의
도달은 이번 오프라인 검증에서 확인하지 못했다.

## 판단

Luna가 관측을 놓치거나 일부 결측을 전체 무지로 바꾸는 부담은 줄었다.
기존 관측의 활용, 범위가 제한된 설명 갱신, 직관적 개입을 선택할 경로도
더 명확해졌다. 연구 발전에 필요한 연결을 보완했지만, 좋은 가설을 고르는
능력이나 강한 결과로 수렴하는 능력이 입증된 것은 아니다. 후속 실제 검증은
사람의 연구 조언 없이 기존 관측을 해석하고, 그 해석 때문에 달라진 개입을
작성·비교하는지 확인해야 한다.

## 로컬 검증 범위

관측 경로의 누락·탈출, 실제 nested 값 수집, family 간 근거 전용 금지,
부분 해석의 생성 스키마와 호스트 판정, reviewer의 출력별 확인 누락을
검사했다. 관련 기존 검사와 회귀 검사는 130 passed, 3 subtests passed였다.
focused pyflakes와 `git diff --check`도 통과했다. 이 숫자는 연구 진전의
증거로 사용하지 않는다.

별도 MCP 검사에서는 기존 도구 목록 기대값에 `retrieve_research_source`가
빠진 한 건이 실패했다. 변경 전 HEAD를 임시 디렉터리에 풀어 같은 실패를
재현했다. 이번 변경과 무관한 기대 목록 문제이며 이 작업에서 수정하지 않았다.
