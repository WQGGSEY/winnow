# 협력 대칭 게임: 하네스 검증 입력 계약

2026-09-05 사용자 제안. 이 사례의 목적은 research harness가 문제 접수부터 학습 코드 작성, 실험, 논문 작성까지 수행할 수 있는지 검증하는 것이다. 아직 고착 현상을 재현하지 않았고 새 논문도 생성하지 않았다.

## 하네스에 제공하는 입력

- 사용자의 문제 진술: 대칭성이 있는 협력 게임에서 RL로 전략을 학습할 때 중간 상태에 고착되는 현상을 조사하고 개선하고 싶다. 중간 상태의 운영 정의와 원인은 미확정이다.
- Lab3 게임 규칙, 맵, 관측·행동·보상 인터페이스와 시뮬레이터.
- 연구 실행에 필요한 코드 작성·실행 및 문헌 조회 수단. 도구와 계산 예산은 실제 실행 전에 기록한다.

기존 학습 코드, 체크포인트, 완성된 에이전트, baseline 구현, 과거 보고서와 해결 전략은 제공하지 않는다. 알고리즘 선택, baseline 선정과 구현, 학습 코드, 측정 지표와 실험 설계는 하네스가 작성하고 출처와 실행 이력을 남겨야 한다. 외부에서 작성한 RL 해결책을 하네스의 성과로 기록하지 않는다.

Kaggle에서 조회용으로 내려받았던 학습 소스와 실행 출력의 로컬 작업 사본은 삭제했다. Kaggle 원본은 변경하지 않았다. 계정 인증 정보와 조회 메타데이터도 연구 입력에 포함하지 않는다.

## 게임 입력 생성

`scripts/build_lab3_game_bundle.py`는 Lab3의 고정 커밋 `1468141dd5706ddbb5d4dcb4f5491337cbbf7768`에서 허용한 게임 엔진 파일과 맵만 새 디렉터리에 추출한다. 기존 출력 디렉터리에는 덧씌우지 않는다. 원본 CLI의 정책 로더와 keyboard agent, 점수 export 의존성은 제외한다. 입력 파일과 원본 파일의 해시는 `input_manifest.json`에 기록한다.

입력 번들에는 [게임 인터페이스 설명](lab3-game-interface.md)만 함께 제공한다. 현재 문서와 감사 기록, 전체 Lab3 저장소, Kaggle 자료는 하네스의 게임 입력 디렉터리에 복사하지 않는다. 네 에이전트의 행동은 모두 호출자가 제공한다. 기본 상대 정책이나 reward shaping은 없다.

파일을 분리한 사실만으로 실행 격리가 증명되는 것은 아니다. 실제 평가에서는 하네스가 접근할 수 있는 파일·도구·네트워크와 모든 외부 개입을 기록해야 한다. 게임 번들 생성이나 시뮬레이터 검증은 논문 생성 능력의 검증을 대신하지 않는다.

## 시뮬레이터 검증 기록

`scripts/verify_lab3_game_bundle.py`로 12개 맵, 각 4개 seed의 행동열을 원본 엔진과 추출 엔진에 입력했다. 57,600번의 전이에서 전체 관측과 보상의 해시가 일치했다. 득점 변화 15번, 먹이 상태 변화 201번이 포함됐다. 잘못된 행동·차례를 거부하면서 상태를 보존하는지, 제한 도달 후 추가 행동을 거부하는지도 확인했다. 이 행동열은 검증 스크립트에서만 생성하며 게임 입력 번들에 포함하지 않는다.

기존 출력 디렉터리 덮어쓰기를 거부하는 동작과 입력 파일 해시·파일 목록을 검증했다. 별도로 bubblewrap에서 게임 번들만 읽기 전용으로 연결하고 네트워크와 호스트 홈 디렉터리를 제외한 상태에서 reset과 종료까지 실행했다. 해당 프로세스에서 연구 저장소와 Kaggle 인증 디렉터리에 접근할 수 없음을 확인했다. 전체 하네스의 격리 실행과 학습 코드 생성은 아직 수행하지 않았다.

## 제출 성공 조건

후보 학회는 ICML, NeurIPS, ICLR, CVPR, COLT이며 회차와 트랙은 미정이다. 하네스가 생성한 연구 코드와 실제 실행 증거, 주장과 문헌·실험·증명의 대응, 과학적 검토, 선택한 학회의 제출 패키지를 함께 검증한다. HTML 생성과 형식 검사 통과만으로 완료를 선언하지 않는다.
